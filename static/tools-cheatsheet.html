GitHub Tools

Observe-only repo intelligence. It scans local projects and watchlist repos, then emits Markdown and JSON findings for upgrades, stale tools, risky drift, and useful integrations.

Use when: you want a repo/tool ecosystem scan, a queue of improvement ideas, or a finding you can approve before implementation.

GitHub plugin: github

General GitHub triage and orientation through the connected GitHub app. Use it for repositories, issues, PRs, comments, metadata, and deciding which specialized workflow should take over.

Routes to: gh-address-comments for PR review feedback, gh-fix-ci for failing checks, and yeet for publishing local work.

gh-address-comments

Inspects unresolved PR review threads, clusters actionable feedback, and helps implement selected fixes after scope approval.

Use when: a PR has review comments or requested changes.

gh-fix-ci

Debugs failing GitHub Actions checks using PR metadata, check runs, and logs. It should diagnose first, then wait for approval before applying a fix.

Use when: CI, workflow, test, or Actions checks fail.

yeet

Publishing flow for local changes: confirm scope, branch, stage intended files only, commit, push, and open a draft PR.

Use when: you want current local work packaged and sent to GitHub.

Troubleshooting

Model writes text but does not call tools

Switch to Agent mode, use a model endpoint marked as tool-capable, and include a direct tool instruction such as "use manage_mcp list_tools". Local models may need native tool support or Odysseus parsing fallback.

gbrain direct CLI hangs or locks

When Odysseus is running, its gbrain MCP process can own the PGLite lock. Use the connected MCP server from Odysseus instead of direct CLI calls.

MCP server id changed

Run manage_mcp list and use the current server names. The friendly server name is more stable than the generated id.
